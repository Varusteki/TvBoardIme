# 模拟器（AVD）跨屏联调

## 先说结论

**AVD 和手机无法真正处于同一局域网。** AVD 默认走 QEMU 用户态 NAT，网络里只有一个 `10.0.2.15`
虚拟地址，没有二层桥接；Windows 上的模拟器也不支持 tap 桥接（`-net-tap` 仅 Linux / macOS 有）。
所以手机无论怎么连 Wi-Fi，都没有路由能到 `10.0.2.15`。

能跑通的只有「端口转发 + 地址覆盖」：把模拟器的服务端口映射到 PC，再让二维码写的不是模拟器地址，
而是 PC 的局域网地址。

```
手机 ──→ PC 局域网 IP:8080 ──→ 127.0.0.1:18080（adb forward）──→ 模拟器:8080
              ↑
         中间多一段，因为 adb forward 只监听 127.0.0.1
```

实测 `adb forward tcp:8080 tcp:8080` 之后 `netstat` 显示的是
`TCP 127.0.0.1:8080 LISTENING`——手机连 `192.168.x.x:8080` 会被直接拒掉，
所以需要一个监听 `0.0.0.0` 的小转发器（`scripts/lan-bridge.py`）。

## 步骤

1）起桥接，**一条命令，窗口保持不关**：

```bash
C:\python313\python.exe scripts\lan-bridge.py
```

脚本会自己做完三件事，不需要再开别的终端：

- `adb forward tcp:18080 tcp:8080`（模拟器重启、adb 重连后这条会掉，重跑脚本即可）
- 监听 `0.0.0.0:8080`
- 把本机地址写进模拟器的 `endpoint.txt`，让二维码指向本机

输出大致是：

```
监听 0.0.0.0:8080 → 127.0.0.1:18080
转发进程: C:\python313\python.exe
手机访问地址: http://192.168.1.23:8080
已建立端口映射: tcp:18080 → 模拟器 tcp:8080
已写入二维码地址: 192.168.1.23:8080（键盘收起再弹出即可生效）
```

解释器路径要用本机防火墙已经放行过的那个（见「排查」第 4 条），否则手机连不上、本机却一切正常。

2）让模拟器里的键盘**弹出并保持可见**。HTTP 服务只在键盘可见时存在，键盘一收，8080 就没了。

3）键盘**收起再弹出**一次（让二维码重新读地址），此时二维码内容应为 `http://192.168.1.23:8080`。

4）手机连同一个 Wi-Fi，扫码即可；打字与 `/api/state` 走同一条链路（文件投送已移除）。
   二维码暂时扫不动时，手机浏览器直接开 `http://192.168.1.23:8080` 一样能用。

需要手工控制时，脚本对应的命令是：

```bash
adb forward tcp:18080 tcp:8080
adb shell "run-as com.tvboard.ime sh -c 'echo 192.168.1.23:8080 > /data/data/com.tvboard.ime/files/endpoint.txt'"
```

**必须用 `run-as`，不要用 `adb shell echo > /sdcard/...`。** Android 11+ 的分区存储里，
shell 写进 `/sdcard/Android/data/<pkg>/` 的文件属主是 `shell`，应用自己反而读不到
（`Permission denied`，`chmod 666` 也救不回来，FUSE 按属主判定）。`run-as` 是以应用身份写，
写出的文件应用一定读得到。应用读地址的顺序是「内部 `filesDir` → 外部 `files` 目录」，
两个位置都认，内部优先。

## 排查

打不开时按顺序确认下面**四件事同时成立**，缺一件就必然打不开：

1）**模拟器里的键盘真的弹出来了**。HTTP 服务是跟着 IME 生命周期起的，键盘不显示就没有 8080。
   模拟器默认带硬件键盘，软键盘会被压制，先放开：

   ```bash
   adb shell settings put secure show_ime_with_hard_keyboard 1
   ```

   确认监听（`:1F90` 就是 8080，注意它出现在 `tcp6` 里，是双栈监听，正常）：

   ```bash
   adb shell "cat /proc/net/tcp6" | grep -i ':1F90'
   ```

2）**端口映射在**：`adb forward --list` 应能看到 `emulator-5554 tcp:18080 tcp:8080`。
   掉了就重跑第 1 步（模拟器重启、adb 重连都会掉）。

3）**桥接在跑**：`netstat -ano | findstr :8080` 要能看到 `0.0.0.0:8080 LISTENING`。
   只看到 `127.0.0.1:8080` 说明只是 adb forward，没有桥接。

4）**防火墙放行了这个进程**。这是最容易踩的一处：Windows 的入站规则按**程序路径**记，
   本机现有的放行规则只覆盖 `C:\python313\python.exe`，用别的解释器（例如 WorkBuddy 内置的
   `~/.workbuddy/binaries/python/...`）起的桥接，公网（Public）配置文件下会被静默丢弃——
   表现就是手机一直转圈，而本机 curl 却是通的（本机访问走回环，绕过防火墙）。

   ```bash
   # 用已有放行规则的解释器
   C:\python313\python.exe scripts\lan-bridge.py
   ```

   或者管理员执行一次，按端口放行：

   ```bash
   netsh advfirewall firewall add rule name="tvboard-bridge" dir=in action=allow protocol=TCP localport=8080
   ```

其它对应关系：

| 现象 | 原因 / 处理 |
|---|---|
| 手机上连接超时、一直转圈 | 第 4 条防火墙；或手机与 PC 不在同一网段（公司 Wi-Fi 常开客户端隔离） |
| 连接被拒 / 立刻失败 | 第 1 条键盘没弹（8080 没监听），或第 2 条映射掉了 |
| 二维码还是 10.0.2.15 | 没写 `endpoint.txt`；写了但键盘没重新弹出（没触发 `refreshEndpoint`）；或装的是 release 包（该覆盖只在 debug 生效） |
| 二维码地址对了但页面打不开 | 第 3 条桥接窗口关了，或 `--target-port` 与 `adb forward` 本地端口不一致 |

端口对不上时：先看键盘上二维码里的端口（或 `TransferState`），把两边一起改，例如应用选了 8081：

```bash
adb forward tcp:18080 tcp:8081
adb shell "run-as com.tvboard.ime sh -c 'echo 192.168.1.23:8080 > /data/data/com.tvboard.ime/files/endpoint.txt'"
```

`adb forward` 的本地端口固定用 18080，桥接端口固定 8080 就不用改。

## 取消覆盖

```bash
adb shell "run-as com.tvboard.ime rm -f /data/data/com.tvboard.ime/files/endpoint.txt"
```

再收起弹出键盘，二维码恢复成模拟器自己的地址。release 包不读这个文件
（`BuildConfig.DEBUG` 为 false 时 `DebugEndpoint.read()` 直接返回 null），
所以这个调试口子不会带到正式包里。

## 更省事的替代

真要验证跨屏体验，**用真机电视**：手机和电视连同一个 Wi-Fi，扫码即用，零配置。
AVD 只适合手边没有电视时验证交互与协议。
